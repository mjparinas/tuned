# Tuned: guide for agents

Tuned is a native Android IPTV player. It signs in to an Xtream Codes-style server, a MAC (Stalker) portal, or any M3U and XMLTV link, caches the playlist and guide on the device, keeps them fresh in the background, and plays streams with Media3. The rule for every screen is Melvin's (2026-11-17): **"the UI is clean and intuitive and basically gets out of your way"**, and **speed comes first**. This file holds the rules that apply to every change. The decisions about each area, and why, are in one file per topic under `docs/decisions/` (listed below), so threads working on different areas don't edit the same file. Before working on an area, read its file. If a task seems to need a decision changed, raise it with the owner (Melvin) first.

## Commands

```bash
./gradlew :app:assembleGithubDebug    # debug APK: app/build/outputs/apk/github/debug/app-github-debug.apk (id com.tunedplayer.app.debug)
./gradlew :core:test                  # parser and rule tests, plain JVM, seconds
./gradlew :app:testGithubDebugUnitTest # app unit tests
./gradlew spotlessApply               # format Kotlin (ktlint); CI runs spotlessCheck
./gradlew detekt :app:lintGithubDebug # static analysis and Android Lint; any finding fails
./gradlew :app:generateGithubReleaseBaselineProfile  # baseline profile on an emulator (Baseline profile workflow does it in CI)
./gradlew :smoketest:pixel6Api34GithubDebugAndroidTest  # device smoke test on an emulator (CI runs it on every pull request)
./gradlew :app:testGithubDebugUnitTest -Pscreenshots  # every screen drawn on the JVM with sample data, PNGs in app/build/outputs/roborazzi
npm ci && npm run format              # Prettier for YAML, JSON, Markdown and website HTML/JS/CSS; CI runs format:check
node devices/a11y-check.mjs            # the website against WCAG 2.2 AA (axe, light and dark, 320px, focus); CI runs it
```

`npm ci` also points Git at `scripts/git-hooks/` (prepare), so a **pre-commit** formats staged Prettier files before the commit. Cursor's `.cursor/hooks/` runs Prettier after an agent edits a matching file. Never commit with `--no-verify` to skip that.

## Stack (Melvin, 2026-11-17: "use all modern libraries as much as possible")

Kotlin, Jetpack Compose with Material 3, Navigation Compose (type-safe routes), Room with Paging 3, WorkManager, DataStore, Media3 ExoPlayer (HLS and OkHttp data source), OkHttp, Coil 3, kotlinx.serialization, Play in-app updates and a GitHub Releases updater. Versions live only in `gradle/libs.versions.toml`; Dependabot raises them weekly. Liftsmith's Android app is a web app in a Capacitor shell; Tuned is fully native because a WebView player can't match Media3 on start time, codecs, captions or picture-in-picture ([architecture](docs/decisions/architecture.md)). What it shares with Liftsmith is the dev tooling: this file and `docs/decisions/`, pull requests into `staging`, promotion to `main`, one required "CI passed" check, Dependabot, Canadian English, and formatting and lint that fail CI.

## Modules

- `:core`: plain Kotlin, no Android. The M3U and XMLTV parsers, sorting streams into Live TV, Movies and Shows, country detection, episode numbering, Xtream URLs. Anything that can be tested without a device goes here, with a test. It runs on Android 8.0 (minSdk 26), so it may only call Java that Android 8.0 has (`URLEncoder.encode(s, "UTF-8")`, never the `Charset` overload); Animal Sniffer fails CI otherwise ([diagnostics](docs/decisions/diagnostics.md)).
- `:data`: Android library, no flavours: Room (`data/db/`), DataStore settings (`data/Settings.kt`, `data/SettingFields.kt`), the encrypted login, accounts, downloads, imports, and the log (`diagnostics/AppLog.kt`, `diagnostics/Safely.kt`). It compiles once for both builds and comes from the build cache when a change leaves it alone ([architecture](docs/decisions/architecture.md)). A file that needs `R`, a WorkManager job, a widget, the player, `AppContainer` or a github or play difference stays in `:app`, in the same package (`data/PlaylistSession.kt`, `data/AppReset.kt`, `data/TunedAccount.kt`, `diagnostics/CrashReporter.kt` and others); everything else under `data/` goes in `:data`.
- Application id and Kotlin package: `com.tunedplayer.app` (Melvin, 2026-11-19; `app.tuned` up to 1.13, a separate app to Android, [updates](docs/decisions/updates.md#application-id-melvin-2026-11-19)).
- `:app`: the Android app, in three builds ([premium](docs/decisions/premium.md)): `github` (GitHub Releases, updates itself, everything unlocked), `play` (Google Play: no self-updater, Premium sold through Play Billing) and `amazon` (the Amazon Appstore on Fire TV, Melvin 2026-11-27: no Google Play services at all, so no Play Billing, Play updates or Chromecast, and Premium comes only from the Tuned account; [TV](docs/decisions/tv.md#fire-tv)). `BuildConfig.STORE` names the build; code that needs Google Play services must work without them. No build fills in a server (Melvin, 2026-11-19). Store builds never name a provider, channel or sports brand, in the app or the listing.
- `:app` folders: `data/` (what of it reaches up into the app: switching playlists, sign-out, the Tuned account and its backup), `work/` (background refresh), `player/` (PlayerActivity), `ui/` (Compose screens, one screen and its ViewModel per file).
- `:smoketest`: the github debug app on an emulator: sign in, play, change channel, back, and never two stream connections at once ([diagnostics](docs/decisions/diagnostics.md)).
- `:fakeprovider`: plain Kotlin, the stand-in provider on the loopback that both device test modules use, with a generated clip and no login.
- `devices/`: not Gradle. Tuned's server and website on Vercel: accounts with Google sign-in, device seats, Stripe, backups (Postgres on Neon, `devices/schema.sql`), the admin at `/admin` (`devices/lib/admin/`, `devices/schema-admin.sql`, tests in `devices/lib/admin/*.test.mjs`; [admin](docs/decisions/admin.md)), the Premium device list (`/devices`), the account at `/account` (a side menu and an overview on a desktop, chips on a phone; [website](docs/decisions/website.md#the-account-on-a-desktop-melvin-2026-11-20)), the channel list and guide at `/account/channels` (always on: the app's Live TV guide in a browser, grid, now and next, filters, logos; a click opens VLC or copies the link; read from the copy the app shares (`data/SharedChannels.kt`, `api/account/channels.mjs`) or the provider when there's none, with http logos fetched by `api/account/logo.mjs` (pictures only); every signed-in app keeps that copy, and a device whose first download fails fills Live TV from it (`data/AccountChannels.kt`, [playlist](docs/decisions/playlist.md)) ([web](docs/decisions/web.md#built-the-channel-list))), the Premium web player at `/watch` (Live TV in the browser from that copy, one stream and one browser lease at a time, no relay; behind `web_player`; [web](docs/decisions/web.md#built-the-web-player-at-watch-melvin-2026-11-22)), the provider check at `/check` (also behind `web_player`), managing the account's playlists and settings at `/account/playlists` (it edits the backup, which the app joins with its own; [accounts](docs/decisions/accounts.md#playlists-and-settings-on-the-website)), the daily Getting to know Tuned emails to new accounts and their unsubscribe (`lib/emails.mjs`, `lib/email-series.mjs`, `api/cron/emails.mjs`; [emails](docs/decisions/emails.md)), the relay and page for signing in on a TV with a phone, and the public landing page and blog built from `devices/site/` by `node devices/build-site.mjs` ([website](docs/decisions/website.md)), all styled like the app from `public/site.css` ([branding](docs/decisions/branding.md#the-website-melvin-2026-11-19)); plain Node 26 (`engines` in `devices/package.json`, matching the Vercel project and CI) whose one dependency is Neon's driver, tests in `devices/lib/*.test.mjs` ([accounts](docs/decisions/accounts.md), [premium](docs/decisions/premium.md), [onboarding](docs/decisions/onboarding.md)).
- `tv/`: Tuned for other TVs ([Samsung TVs](docs/decisions/tizen.md)). `tv/core` (Gradle `:tvcore`) compiles :core's plain-Kotlin files to JavaScript (the list is in its `build.gradle.kts`); a file there may only call Kotlin and `Platform` (`JvmPlatform.kt` on Android, `tv/core`'s own `Platform.kt` in JavaScript), so a Java call in one of those files breaks the TV build. `tv/shared` (`@tuned/shared`) is plain TypeScript both TV apps share below their screens (playlist, guide, account, phone sign-in, the one-connection guard), with `fetch`, storage and crypto handed in; tests with `npm test` there. `tv/tizen` is the Samsung app.
- `:baselineprofile`: drives the release app on an emulator to write its baseline profile and measure cold start ([speed](docs/decisions/speed.md)).

## Product rules

- **Get out of the way.** Opening the app shows channels from the cache at once; nothing waits on the network. The player shows only video until a tap; the controls hide themselves, and with them the time of day and the stream's pills ([player](docs/decisions/player.md)). The player's tools are buttons in its top row, never behind a three-dot menu (Melvin, 2026-11-19). While a TV plays, the phone is a remote for it, never the stale frame: what the TV is doing in words, the controls always up, volume and Stop casting, and a spinner only while something loads (Melvin, 2026-11-21; [player](docs/decisions/player.md)). No pop-ups, no onboarding beyond adding a first playlist ([onboarding](docs/decisions/onboarding.md)). Filters chosen on the browse tabs stay chosen until changed, per profile, even after the app closes (Melvin, 2026-11-21; [playlist](docs/decisions/playlist.md)).
- **Speed first** ([speed](docs/decisions/speed.md)): lists are paged straight from Room; downloads stream into the database in batches; nothing heavy runs before the first frame, and background work (backup, refreshes, downloads, scans) waits on `QuietStart` until the first screen is up (Melvin, 2026-11-20); new background work does too. Speculative warm (`BrowseWarm`) anticipates the next browse screens (Room first pages, Coil disk, bounded TMDB) while a profile is picked or Home sits idle — never streams. SQL through `openHelper` starts with `offMain` (`data/db/OffMain.kt`), because Room only moves its own DAO calls off the screen thread.
- **Waiting is never a mystery** (Melvin, 2026-11-20: "If you know how large the download is, you should show me the real progress and how much and total size"). Anything long shows real progress where it can (bytes of the full size, or bytes so far when the size isn't known) and names each step it goes through, numbered, rather than one moving bar ([playlist](docs/decisions/playlist.md)). When the size or count is known and the job has been moving long enough to guess, the same line also says about how much longer it will take from the current rate ("about 3 min left"; Melvin, 2026-11-22), for Top rated fills, refreshes, offline downloads, channel scans and update installs (`core/Eta`, `ui/ProgressEta`). **Anything that refreshes, downloads or syncs always shows a spinner or progress**, on a phone and a TV, from the tap until it ends, including while it waits to start: a tap that starts work answers at once (a spinner where the button was, a line saying what is happening) and then says how it ended, with Try again on a failure (Melvin, 2026-11-21: "there needs to be some user feedback so they know that the app didn't just crash or freeze", and "same thing for anything related to refreshing or downloading or syncing. There should always be some type of feedback that something's happening"; the update install in [updates](docs/decisions/updates.md), Settings' buttons in [settings](docs/decisions/settings.md#every-button-says-it-did-something-melvin-2026-11-21)).
- **Customizable** (Melvin, 2026-11-17: "customizing most things in the settings"): a new behaviour gets a setting when people could reasonably want it either way, with the common choice as the default.
- **Emails sell by showing, never by nagging** ([emails](docs/decisions/emails.md); Melvin, 2026-11-26). Every email to a person is `tunedMail` (`devices/lib/emails.mjs`): Tuned's dark look, a real screen or drawn graphic, says Tuned provides no content, and carries the one-click unsubscribe and postal address. A feature that ships and a person would notice gets an email in `email-series.mjs`; Premium-only features are marked Premium in the email.
- **Never ask for, log or commit a login.** The app stores it encrypted until sign-out ([security](docs/decisions/security.md)), and signing out resets the app to how it was installed, keeping downloads only if the person chooses to ([onboarding](docs/decisions/onboarding.md#sign-out)); a new store of data must be cleared by `data/AppReset`. Error messages go through `XtreamUrls.redact`; log lines through `AppLog`, which scrubs them ([diagnostics](docs/decisions/diagnostics.md)). Playlists and guides are never committed (`.gitignore` blocks `*.m3u`, `*.xmltv`, `.env`).
- **One stream connection, ever** (Melvin, 2026-11-17: "i dont want to get banned"). The player, auto-tune, backup copies, channel scans and downloads share one connection: the old stream closes before the next opens, nothing prefetches, and there is no multi-view or live preview ([scope](docs/decisions/scope.md)). **Watching comes first** (Melvin, 2026-11-18: "the app should prioritize the stream and have the downloads wait"): a download is a stream connection too, so while anything plays (the player, picture-in-picture, background play, the next episode, or a cast to a TV, which carries on while the app is in the background) downloads and channel scans stop and wait, the download hangs up before the stream opens, and they carry on when watching ends ([offline](docs/decisions/offline.md)).
- **Saved before streamed.** Anything downloaded plays from the device, never the stream ([offline](docs/decisions/offline.md)). TMDB art and details come from the device's cache first and the network only for what's missing ([player](docs/decisions/player.md)).
- **Real names over numbers.** Show an episode's TMDB name where there is one, rather than "S1 E1" (Melvin, 2026-11-17).
- **No second video on screen, and no sleep timer** (Melvin, 2026-11-17). Android's picture-in-picture, the one stream shrinking to a small window when you leave the app, stays, and Back on live TV shrinks it the same way to browse while it plays (the mini player, Melvin, 2026-11-21); anything new picked closes it before its stream opens ([player](docs/decisions/player.md)). A second channel inset over the first is banned because it is a second stream. Don't build or propose a sleep timer ([scope](docs/decisions/scope.md)).
- **English is Canadian English** (as in Liftsmith): colour, favourite, behaviour, centre, cancelled, but -ize (organize). Code identifiers stay as they are.

## Code conventions

- Formatting is ktlint's (`.editorconfig`, width 140) through Spotless, and Prettier's for YAML, JSON, Markdown and the website's HTML/JS/CSS. Don't hand-format. Before every commit that touches those files, run `npm run format` (or rely on the pre-commit hook after `npm ci`); CI's Formatting job fails otherwise (Melvin, 2026-11-24: "can you fix prettier, it always fails").
- detekt (`config/detekt/detekt.yml`) and Android Lint (`warningsAsErrors`) fail CI on any finding. Fix the cause; suppress only with a comment saying why.
- Every string a person reads is in `res/values/strings.xml`; numbers that change a word use `<plurals>`. **The app is translated into 11 languages** ([languages](docs/decisions/languages.md); Melvin, 2026-11-20): a new or changed string gets its translation in every `values-xx` folder in the same pull request (Lint's `MissingTranslation` fails otherwise), "Tuned" is never translated, and the device's language picks the app's, with no picker in the app.
- **Pop-ups are `TunedDialog`** (`ui/common/TunedDialog.kt`), never Material's `AlertDialog` directly (detekt enforces it), so every dialog keeps 24 dp off the screen's edges, stops at 560 dp (720 dp, `DialogWideMaxWidth`, for a TV's sign-in code dialog and for Report a problem, which is nearly a phone's width; Melvin, 2026-11-21: "Can you make this wider?") and sits in the centre (Melvin, 2026-11-19: "these pop ups shouldn't take the full width"; [branding](docs/decisions/branding.md)). A panel that slides up from the bottom is `TunedSheet` (`ui/common/TunedSheet.kt`), never Material's `ModalBottomSheet` directly (detekt enforces it): a bottom sheet on a phone, and on a TV a full-screen window inside the overscan margin that keeps the remote's focus inside it, with no drag handle and Back to close (Melvin, 2026-11-21: "Dragging handles shouldn't really be on the TV app"; [TV](docs/decisions/tv.md)). A code to type elsewhere is `OneLineCode`, which never wraps (Melvin, 2026-11-20: "I don't ever want to see the code text wrapped").
- **The website's dropdowns are Tuned's own** (`devices/public/select.js` and `select.css`; Melvin, 2026-11-21: "make it our own custom component"), never the browser's: a new `<select>` on any page, the admin included, gets `enhanceSelect` (or the admin's `watchSelects`) ([website](docs/decisions/website.md#dropdowns-are-tuneds-own-melvin-2026-11-21)).
- **TV-safe** ([TV](docs/decisions/tv.md)): on a TV every screen sits inside the overscan margin (`TvSafeArea`, 12 dp sides and 16 dp top and bottom by default, shifted and scaled by Settings › Appearance › Calibrate screen; Melvin, 2026-11-22), and a screen's own backdrop (a glow, a gradient) still fills the whole screen through `bleedIntoTvMargin`, so no frame shows around it; a screen taller than 540 dp less that margin must scroll or change layout so nothing is cut off. A screen opens with the remote on the likely choice (the first item of a list, Play on a film, the first profile on "Who's watching?") through `TvFocus` or `startFocus`, so OK alone does it. On a TV, up and down always move between rows and left and right adjust (a slider moves a step; it never takes up or down), and whatever the remote is on shows the accent outline (`focusRing`) or the stronger focus shade (`TvFocusShade`). A clickable row with a button at its end does that button's job when the button is the likely choice, because the remote lands on the row (Settings › Check for updates installs a waiting update; [updates](docs/decisions/updates.md)). Tuned's mark and name sit in a TV screen's upper left (`TvBrand`: atop Home's rail, leading every `BackTopBar`), and a TV's system theme is dark.
- **Accessible by default** ([accessibility](docs/decisions/accessibility.md)): an icon-only button has a label, a state shown by colour is also given in words, switches are `toggleable`, tap targets are 48dp, and text containers use a minimum height, never a fixed one.
- **Defensive by default** (Melvin, 2026-11-20: "Ensure the android app uses defensive programming. Catch all errors, write any errors to the logs. Make it so the app doesn't crash at all"; [diagnostics](docs/decisions/diagnostics.md)). Fire-and-forget coroutines use `launchSafely(tag)`, with `onError` resetting any "busy" state so a button never stays stuck. Caught failures go to `AppLog` (`attempt` instead of `runCatching`), so nothing fails silently. A network or parse call catches more than `IOException` (a bad address, an unreadable answer and a bug fail differently) but always lets `CancellationException` through, so a cancelled job stops. Background jobs run inside `logFailures`. Anything still missed reaches `CrashReporter`, which logs it and keeps the app going, or restarts it on its home screen when the screen thread itself failed; that is the last resort, not a reason to skip handling.
- **Where new code goes, so parallel work doesn't collide.** Add to the file for your area, inside its area, never at the end of a shared list. A new setting is one field in `AppSettings` (`data/Settings.kt` in `:data`) and one line in its area of `SETTING_FIELDS` (`data/SettingFields.kt` in `:data`); its row goes in that page's file (`ui/settings/SettingsPlayback.kt` and so on; [settings](docs/decisions/settings.md)). A row that opens another screen passes its route to `onOpen`, so `SettingsScreen` and `MainActivity` don't change. Stored key names never change (a test pins them).
- **Big files are split by area so features land side by side.** Each DAO has its own file in `data/db/` (shared SQL filters in `DaoQueries.kt`), entities are grouped by table (`ItemEntities.kt`, `LibraryEntities.kt` and so on), the Home screen's tabs have their own files (`LiveList.kt`, `Grids.kt`, `Posters.kt`), and `AppContainer.kt` only builds the app's shared objects; switching, removing and signing out of playlists is `PlaylistSession`. Put new code in the file for its area rather than growing a shared one. Two pull requests that both bump the database version: the one that merges second renumbers its migration and schema file when it merges `staging` in.
- **A new screen** is a route and a `composable<…>` in its feature's navigation file (`ui/PlaylistNav.kt`, `ui/BrowseNav.kt`, `ui/SettingsNav.kt`), not in `MainActivity`. Moves several screens share (play, tune, open a person, go home) are on `AppNav`.
- **A player feature** lives in its own file in `player/` (as `SkipIntro`, `Backups`, `SubtitleSearch`, `PlaybackProgress` and `PlayerMedia` do), and `PlayerActivity` only creates it and calls its hooks, so the activity grows by a few lines per feature rather than by the feature. `PlayerActivity` sits at detekt's `LargeClass` limit (599 of 600 lines of code, not counting its companion object or the anonymous listener inside it), so a feature that adds a line to it takes one out, for example by wiring itself up from its own constructor as `MiniPlayer.Screen` does.
- **Screenshots for every new feature** (Melvin, 2026-11-18: "i would like to see screenshots for all new features posted in these chats"; [screenshots](docs/decisions/screenshots.md)). A pull request that changes what a person sees adds or updates its picture in `app/src/test/kotlin/com/tunedplayer/app/screenshots/` (a route and the text to wait for), adds the `screenshots` label, and posts the pictures from the `screenshots/<branch>` branch in its thread. They are drawn on the JVM in minutes; no build or emulator.
- A bug fix comes with a test that fails without it. Flaky tests are fixed at the cause, never retried.

## CI/CD (like Liftsmith)

- `ci.yml` on every pull request and push to `main` and `staging`: formatting (Prettier, ktlint), lint and static analysis (detekt, Android Lint), unit tests, the device smoke test on an emulator, and the Android build (an unsigned release build so R8 problems show up here; no debug APK, because Melvin installs only production releases, 2026-11-18). **"CI passed"** is the one required check. Each run does only what the change needs (`scripts/ci-changes.mjs`, with tests; Melvin, 2026-11-19): a tree that already passed skips everything, so `main` reruns nothing after a promotion and the push to `staging` after a merge reruns nothing when staging didn't move while the pull request was checked (a commit pushed with GITHUB_TOKEN, which starts no CI, is vouched for by a parent with exactly the same files; Melvin, 2026-11-21: "Is it possible to speed up ci without affecting safety"); Markdown or `docs/` only runs just Prettier and the decision-record check ("dont run ci if there are only markdown file changes"); the website alone (`devices/`) skips the app's Gradle jobs, and the app alone skips the website's tests ("if there are only changes to the web app, only build the webapp and skip mobile builds and vice versa"); anything shared (workflows, `scripts/`, `package.json`) runs both. Skipped jobs count as passed, so "CI passed" still goes green. Kept fast (Melvin, 2026-11-19: "ci cd for this app is quite slow"): the account runs 20 jobs at a time, so every job a run adds holds up the next pull request. ktlint, detekt, Android Lint and the unit tests share one job that compiles the debug app once, Formatting is Node only, the Android build skips the release lint pass (lintVital) that repeats Android Lint (Release still runs it), and the Android test runtime Robolectric downloads is cached (`.github/actions/robolectric-cache`) so a slow Maven Central can't fail the tests. Pull requests only read the Gradle cache; a merge into staging that touched the app and already passed runs the three Gradle cache jobs, which build what Checks, the Android build and the smoke test build (the smoke test's APKs without an emulator) under the same cache names so the next pull request starts warm, and "CI passed" doesn't wait for them (2026-11-21). Add a new check to an existing job rather than a new job.
- `promote-staging.yml`: `main` is production and every pull request targets `staging`. The website deploys itself from Vercel's Git integration: `main` to production (tunedplayer.com), every other branch, `staging` included, to a preview, and `devices/vercel.json`'s `ignoreCommand` skips a deploy when `devices/` didn't change. Run by hand, it promotes staging to main when "CI passed" is green (a direct merge, so it needs no repository setting), then merges main back into staging. **Every production release needs Melvin's go-ahead, each time** (2026-11-17; he holds releases until a batch of features is in), so the nightly schedule Liftsmith uses is off.
- `release.yml`: on every promotion and on demand, a signed APK published as a **GitHub release** (`v<version>`, no build number), which installed copies offer to update to; plus a signed App Bundle for the Play **internal** track once its secret exists ([updates](docs/decisions/updates.md)). The version is semver, bumped automatically from the commits since the last release (`scripts/next-version.mjs`; `package.json` is a floor), and the version code comes from it (1.2.3 is 1002003). The version is worked out once, the APK and the bundle build on two runners at once, and nothing is published until both have built (2026-11-21, about 13 minutes on one runner). Skips with a notice until its secrets exist.
- `screenshots.yml`: not part of CI and not required. On a pull request labelled `screenshots` (or run by hand), it draws every screen and pushes the PNGs to `screenshots/<branch>` ([screenshots](docs/decisions/screenshots.md)).
- Secrets: `ANDROID_KEYSTORE_B64` (base64 upload keystore, alias `upload`), `ANDROID_KEYSTORE_PASSWORD`, `PLAY_SERVICE_ACCOUNT_JSON`, optional `PROMOTE_TOKEN`. The app's own service keys (`TMDB_API_KEY` for ratings and details, `OPENSUBTITLES_API_KEY` for subtitle search, and the others each feature adds) are release secrets built into `BuildConfig`, never committed and never typed into Settings; a build without one hides that feature. The first upload must be done by hand in Play Console before the API can upload.
- **Pull request titles follow Conventional Commits**, because the squashed title decides the next version (Melvin, 2026-11-17: "Auto bump semver versions with each update"): `feat: …` bumps the minor, `fix: …` and anything else the patch, `feat!: …` or a `BREAKING CHANGE:` line the major.
- Dependabot targets `staging` weekly: Gradle (minor and patch grouped), npm, GitHub Actions.

## How work lands (Melvin, 2026-11-17)

- One pull request per feature or fix, into `staging`. Merge it yourself once "CI passed" is green, and fix failing checks and merge conflicts without asking ("auto merge ci when done, auto fix conflicts and ci"). Ask Melvin only for what needs him: secrets, keys, money, or a choice that changes the product.
- Production (staging to `main`, which publishes a GitHub release) only with his go-ahead, each time.
- Raw speed, resilience and reliability come first in every trade-off. Measure speed work before and after, and report it in plain numbers.

## Decision record

Melvin, 2026-11-17: his product and development decisions "should be updated and kept in sync every time new features are added or removed". So:

- **Every pull request that adds, changes or removes a feature updates the record in the same pull request**: the topic's file in `docs/decisions/` (what was decided, Melvin's words and the date, and why), and this file when a rule that applies everywhere changes. A removed feature's text is deleted or marked as removed, never left describing code that is gone.
- A decision made in chat before it is built goes in [scope](docs/decisions/scope.md) under "Decided, being built", and moves to its topic when it merges. Things Melvin ruled out go there too, so nobody suggests them again.
- CI enforces it: the **Decision record** job (`scripts/decision-record.mjs`, with tests) fails a pull request whose title is `feat…:`, breaking (`!`), a revert, or says remove, drop or delete, unless it changes `AGENTS.md` or a file in `docs/decisions/`.

- [Accounts](docs/decisions/accounts.md): the Tuned account (Google sign-in), seats per account and extra seats, Stripe, backups on our server.
- [Admin](docs/decisions/admin.md): the admin at `/admin` on the server's website, its 15 sections, two-step sign-in, and the anonymous usage stats, website counter, codes and flags behind it.
- [Architecture](docs/decisions/architecture.md): native Kotlin over Capacitor, modules, data flow.
- [Auto-tune](docs/decisions/auto-tune.md): finding a working English stream for a live event, one connection at a time.
- [Branding](docs/decisions/branding.md): name, the channel stack icon, colours, themes.
- [Channel scan](docs/decisions/channel-scan.md): finding dead channels without blaming them for the internet or the server.
- [Diagnostics](docs/decisions/diagnostics.md): crash reports, `launchSafely` and `attempt`, the log in Settings, keeping logins out of it.
- [Emails](docs/decisions/emails.md): the daily Getting to know Tuned emails after sign-up (free, Premium, tips, craft), their look, unsubscribe, and the admin alerts in the same look.
- [Languages](docs/decisions/languages.md): the 11 translations, the device's language picks one, what stays untranslated, right to left.
- [Large screens](docs/decisions/large-screens.md): navigation rail, list and detail panes, the guide beside the player on tablets.
- [Lists](docs/decisions/lists.md): Favourites and your own lists beside it, like a music app's playlists; renaming channels and changing logos.
- [Live events](docs/decisions/events.md): today's games and fights from the guide, or from a pay-per-view slot's name when its guide is empty (`core/ChannelEvents`), Tune, following and alerts.
- [Offline downloads](docs/decisions/offline.md): saving films and episodes, one connection at a time.
- [Onboarding and playlists](docs/decisions/onboarding.md): the welcome screen, one form per playlist kind (Xtream, link, file, MAC portal), Settings › Playlists.
- [People](docs/decisions/people.md): actor filmography pages, oldest first, with what is in the playlist marked.
- [Playlist and guide](docs/decisions/playlist.md): Xtream URLs, how streams are sorted, sorting Movies and Shows (newest, year, rating as the poster shows it, A to Z), countries and adult categories across providers, refresh.
- [Player](docs/decisions/player.md): Media3 setup, controls, captions, audio, cast, backup copies, TMDB details.
- [Premium](docs/decisions/premium.md): the free app, the Premium unlock, prices, the GitHub and store builds, store policy.
- [Profiles](docs/decisions/profiles.md): who's watching, kids profiles, profile PINs.
- [Scope](docs/decisions/scope.md): what Tuned will never do, and what's decided but not built yet.
- [Screenshots](docs/decisions/screenshots.md): every screen drawn on the JVM with sample data, the on-demand Screenshots workflow, posting them for each feature.
- [Security](docs/decisions/security.md): login storage, cleartext HTTP, Android backup off (backup files removed 2026-11-18).
- [Settings](docs/decisions/settings.md): the pages of Settings and what goes where.
- [Samsung TVs](docs/decisions/tizen.md): the Tizen web app on AVPlay, :core compiled to JavaScript (`tv/core`), what the TV apps share (`tv/shared`), Premium through the account, what's left out on a TV web app.
- [Simkl](docs/decisions/simkl.md): signing in with a code, scrobbling films and episodes, importing watched history, the app's keys (alongside Trakt).
- [Speed](docs/decisions/speed.md): what keeps the app fast, and the budget.
- [Sync](docs/decisions/sync.md): removed. Google Drive sync, replaced by the backup in the Tuned account (2026-11-19).
- [Trakt](docs/decisions/trakt.md): signing in with a code, scrobbling films and episodes, the app's keys.
- [TV](docs/decisions/tv.md): Android TV launcher, focus outlines, remote keys in the player, and Fire TV (the `amazon` build).
- [Updates](docs/decisions/updates.md): GitHub Releases updater now, Play in-app updates later, semver tags, the application id and moving from `app.tuned`.
- [Web player](docs/decisions/web.md): paused (2026-11-19). Premium playback in a browser with no relaying, and the provider check at `/check` behind a flag: signed in, it checks a saved playlist, and a failed check can still try playing one channel.
- [Website](docs/decisions/website.md): the landing page on www.tunedplayer.com, the features list, store badges, the blog with a post per release, sitemap and robots, WCAG 2.2 AA and its check in CI.
