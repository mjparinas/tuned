# Onboarding and playlists

**Several playlists, added one at a time** (Melvin, 2026-11-17: "support multiple playlist streams… adding the username and password login on the main page doesn't really make sense… make it easy for users to add those"). The first screen no longer asks for a server, username, password and two links at once.

- **Welcome** (first run only): the brand, one line ("Add a playlist from your TV provider to start watching"), and three cards for what providers hand out: **Xtream Codes login**, **Playlist link** (M3U or M3U8, with an optional guide link) and **Playlist file** (an `.m3u` on the device). There is nothing else to get through: no tour, no permissions.
- **One form per kind**, each with an optional name ("Sports", "Living room"). The Xtream form keeps the default server (`http://eros4k.ddns.net`) filled in and still checks the login with the server's small account answer before opening the app.
- **Pasted links are read for what they are** (`core/PlaylistLink`). A `get.php` or `player_api.php` link with a username and password becomes an Xtream login, so catch-up and account status work too; pasted into the Xtream server box, it fills in all three fields. Anything else that looks like a web address is a plain link, with `http://` added when missing.
- **Files are copied into the app** (`files/playlists/`, one file each), so the playlist still loads after the original is moved or deleted, and refreshes read it from there instead of the network. A file that doesn't start like an M3U playlist is refused. Files aren't synced to other devices, since they belong to this one.
- **The guide of a plain playlist** is the link given, else the one its `#EXTM3U` line names (`x-tvg-url`, `url-tvg` or `tvg-url`), read while the playlist is saved. Without either, there is no guide, rather than asking the default Xtream server for one.

**Settings › Playlists** is a full screen: every saved playlist with its name, kind and where it comes from (never the password), a check on the one in use, and a menu to rename, edit or remove it. Tapping another switches to it. "Add a playlist" opens the same three cards. Adding a playlist makes it the one in use. Editing the one in use reloads it; editing another only saves it. Removing the one in use switches to the next; removing the last one signs out (with a warning) and shows the welcome screen. The Settings row reads the playlist in use and how many are saved. The old Server and Username rows are gone, since they meant nothing for a link or a file; the server is edited from the playlist's Edit.

**One playlist at a time.** The app still holds one playlist's channels and guide (switching clears them and downloads the other), so lists, search and favourites never mix providers and the database stays small. When the first download fails, "Change playlist" opens Settings › Playlists instead of signing out.

**Sync between devices** carries every saved playlist except files ([sync](sync.md)). Backup files were removed (Melvin, 2026-11-18).

## Sign in on a TV with your phone

Melvin, 2026-11-19: "if i install this on an android tv, entering in the url to the iptv stream, username and password is very much a pain when you use the remote". From the plan he picked the TV code and QR, sending from the phone app, and the website form ("do a, b, d"), on the existing Vercel project ("use the vercel one"), sending everything from the app ("i want it to sync everything if possible"), free, and no playlist files ("leave out").

- **On the TV** the welcome screen (and Add a playlist) starts with "Sign in with your phone": a QR code and an eight-character code (`K7QF-29MD`) that lasts 10 minutes and then makes a new one by itself. Typing on the TV is still there underneath.
- **A phone without Tuned** scans the QR with its camera and gets `tuned-devices.vercel.app/tv`: the Xtream login or a playlist link, with a pasted `get.php` link filling in the login as in the app. Someone who can't scan types the code there instead, and both screens show the same four digits to check.
- **A phone with Tuned** opens the app from the QR (an app link) or from Settings › Playlists › Send to a TV, and sends what sync between devices sends: every saved playlist except files, settings, favourites, your lists and watch later. It is free, unlike Drive sync, because it is a one-time copy at set-up.
- **The TV shows what arrived** (the playlist names, never a password) and saves it only when OK is pressed, so someone who reads the code off the screen can't add a playlist unseen.

**Nobody but the TV can read it** (`core/TvHandoff`, `devices/public/tv/seal.js`, `devices/lib/tv.mjs`, all tested, and a test opens a box the page sealed with the Kotlin code). The TV makes a one-time P-256 key pair; the QR link carries the public key after `#`, which browsers never send to a server. The phone seals with ECDH, HKDF-SHA256 and AES-256-GCM, with the code bound in. The relay keeps the key, a hash of the TV's poll secret and the sealed box under a hash of the code, for 10 minutes at most, deletes the box when the TV takes it, and limits codes and lookups per visitor. On the typed-code path the relay hands the phone the TV's key, so the four digits (from a hash of the key) prove it's the TV's own. P-256 rather than X25519 because every Android version Tuned runs on, Samsung's TV browsers since 2018 and every phone browser have it, so a Tizen Tuned can use the same relay. The page is served by the relay, so on the no-app path the page's code is what keeps the login private; it loads no third-party scripts and the project's Content-Security-Policy allows only its own.

**Not built, and why:** a phone keyboard linked to the TV (the Google TV and SmartThings apps already type into any field, and it still means typing the login), and a page served by the TV over Wi-Fi with no server (Samsung TV apps can't listen on a port, and it fails on guest Wi-Fi and phones on mobile data).

**App links** need the relay's `/.well-known/assetlinks.json` to list each signing key: it has the GitHub release key. The Play build's app-signing key goes there once the app is in Play Console; until then that build's QR opens the page, which links to the app with `tuned://tv`.
