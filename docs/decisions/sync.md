# Sync between devices

From the app audit, Melvin picked sync between his phone and TV (item 13), and chose "Your Google account (Drive app folder)" over a Tuned server or no cloud at all (2026-11-17), so there's no server of our own to run.

**What syncs** (`SyncCopyRepository.syncCopy`). The saved playlists, every setting, favourites, your own lists ([lists](lists.md)) and watch later. Which playlist is in use stays each device's own, so the phone and the TV can watch different ones. A device with no playlist in use starts on the first synced one and downloads it. Device-only settings (sync times, the open tab, the sound delay) never sync.

**No passphrase** (Melvin, 2026-11-18: "i dont think we need encryption", picking "No passphrase, logins sync" over keeping the lock or leaving logins out). The copy goes to Drive as a plain JSON file, logins included, so signing in to Google is the whole setup on each device. The file ("Tuned sync") is visible in My Drive, so anyone who gets into the Google account could read the logins; Melvin accepted that. The fingerprint stored beside the file is a plain SHA-256 of the copy (`core/CloudSync.fingerprint`). A copy an older version locked with a passphrase is opened once with the passphrase that device still holds (`core/PassphraseCrypto`, kept only for this) and replaced with a plain one; a device without it sends its own copy instead.

**Google sign-in** (`data/GoogleDrive`). Google's sign-in with a code for TVs and other devices, on phones too: Settings shows a short code and google.com/device, which works the same from a phone or a TV remote, needs no Google Play services, and Tuned never sees the Google password. A button beside the code copies it, as on the Trakt sign-in (Melvin, 2026-11-18). It asks only for `drive.file`: Tuned sees the one file it creates in the person's Drive ("Tuned sync") and nothing else of theirs. It first asked for `drive.appdata`, the hidden app folder, but Google's sign-in with a code refuses that scope ("Invalid device flow scope", found 2026-11-18 when Melvin reported "Google drive sync doesn't work"), so sync never signed in. The file is visible in My Drive; deleting it only means the next run sends this device's copy again. The refresh token is sealed with a Keystore key and is never synced; Stop syncing signs out and tells Google to drop it.

**When sign-in fails, say why** (Melvin, 2026-11-18: "Google drive sync doesn't work"). Every failed step used to read "Couldn't reach Google", which hid setup problems on Google's side. Now the dialog names the cause (`core/CloudSync.failure`, with tests) and shows Google's own error under it ("Google said: invalid_client: …"), and the developer log records it: no network, an unknown client ID, a client that isn't the "TVs and Limited Input devices" kind, a wrong client secret, the scope refused, access denied (in Testing, only test users can sign in), or the code running out. A Drive API that is turned off in the Cloud project shows as its own status under Sync now rather than as "offline". The keys are trimmed, so a stray space pasted into the GitHub secret can't break sign-in.

**When it runs** (`work/CloudSyncWorker`). When the app opens (to take another device's changes) and when it leaves the screen (to send this one's), once there's a network, retrying later if Drive can't be reached. Settings › Playlists and account › Sync now runs it at once. Nothing on screen waits for it.

**Who wins** (`core/CloudSync.decide`, with tests). The whole copy, newest change wins: if only one device changed, its copy wins; if both did, the later change does. A new device takes what's already in Drive rather than overwriting it. Favourites and watch later are replaced by the winning copy, so removing one on the phone removes it on the TV. Merging item by item is not done yet: two devices changing different settings at the same moment keep only the later device's.

**The app's keys.** Google's "TVs and Limited Input devices" OAuth client comes from the release workflow's secrets `GOOGLE_TV_CLIENT_ID` and `GOOGLE_TV_CLIENT_SECRET` into `BuildConfig`, never committed. A build without them hides sync. Like Trakt's, this kind of client ships its secret in the app by Google's design; it identifies the app, not the person.
