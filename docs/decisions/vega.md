# Vega OS (newest Fire TV sticks)

**Decided** (Melvin, 2026-11-27: "how to get this working on vega os", then "build both vega and tizen"). Some Fire TV sticks sold from 2025 (the Fire TV Stick 4K Select and later) run Vega OS, Amazon's Linux system, instead of Fire OS. They can't install an Android APK, so the `amazon` build ([TV](tv.md#fire-tv)) never reaches them. Tuned for Vega is its own app in `tv/vega/`, built with Amazon's Vega SDK, and shares the non-screen logic with the Samsung TV app in `tv/tizen/` through `tv/shared/` (`@tuned/shared`).

## How it's built

| Option                                                              | Verdict      | Why                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **React Native for Vega + Amazon's W3C media player**               | **Chosen**   | Amazon's main route for Vega apps. The player (`@amazon-devices/react-native-w3cmedia`, `VideoPlayer` drawn into a `KeplerVideoSurfaceView`) is the stick's own GStreamer pipeline with hardware decoding, and in its URL mode plays MPEG-TS, MP4, MKV, AVI and MOV links directly. Xtream live channels are `.ts` links, so a channel starts without any JavaScript demuxing. |
| WebView app (`@amazon-devices/webview`) hosting the Samsung web app | No           | It would reuse the Samsung screens, but video would go through the web engine's `<video>`, which can't play a raw MPEG-TS link: every live channel would need mpegts.js turning TS into MSE segments in JavaScript on a stick's CPU, the slowest way to a first frame. Speed comes first.                                                                                      |
| Kotlin or Compose                                                   | Not possible | Vega runs no JVM and no Android.                                                                                                                                                                                                                                                                                                                                               |

- **React Native 0.83** with `@amazon-devices/react-native-kepler` 4.x (the Vega runtime), Hermes, TypeScript. Only Amazon's system-distributed libraries and pure JavaScript, so the app's own bundle stays small and the stick shares the runtime across apps.
- **Package id `com.tunedplayer.app`**, component `com.tunedplayer.app.main`, like the Android app (Vega's ids are separate from Android's).
- **Plain HTTP to any host** (`[network-traffic-policy.cleartext] allowed-domains = ["*"]`), since most providers serve `http://`, as on Android ([security](security.md)).
- **Output** is a `.vpkg` per processor: `armv7` for Fire TV sticks (the one the Appstore takes), `aarch64` and `x86_64` for Amazon's Vega Virtual Device.

## What's shared, and with whom

- **`tv/shared/` (`@tuned/shared`)** is owned by the Samsung thread and holds the logic both TV apps need, in plain TypeScript with no screen code and nothing from a browser or React Native, so it runs on a Samsung TV's browser and on Vega's Hermes alike: the Xtream client, the M3U and XMLTV parsers (fed in pieces with `feed`/`end`, since React Native's `fetch` can't stream a body; Vega feeds them from `XMLHttpRequest` progress), the Tuned account client, the storage interface (async strings), and the one-connection player guard. `:core` turns into Kotlin Multiplatform with a JavaScript target for what's already written in Kotlin (`M3uParser`, `Classifier`, `XtreamUrls.redact`, `Search`, `GuideGrid`, `Regions`, `RemoteKeys`), exported as plain ES2015 classes, and the Android app keeps the JVM target unchanged.
- **What Vega takes from `@tuned/shared` (2026-11-27)**: the Tuned account and the phone sign-in (`TunedAccount`: the relay's code, opening the phone's box, the account's token, and the Premium seat with build `vega`), and the logins in what the phone sends (`fromHandoff`). It imports them by subpath (`@tuned/shared/account`, `/login`, `/handoff`, `/bytes`, `/platform`), which need nothing from `tv/core`, so the Vega build needs no Gradle step; Metro watches `tv/shared` and finds its Babel helpers in `tv/vega/node_modules`. The account's keys live under the stick's `tuned:` prefix, so signing out still clears everything.
- **What Vega keeps of its own, and why**: the playlist download (`core/playlist.ts`) reads Live TV first, in 3 steps, and movies and shows afterwards in 4 steps of their own (`downloadLibrary`), so a stick's first screen comes sooner than with the shared loader, which reads everything before it finishes; its Xtream movie, show and episode readers (`core/xtream.ts`) are small TypeScript ports for the same reason, since the shared loader needs `tv/core`'s Kotlin compiled to JavaScript in the stick's bundle and a Gradle step in the Vega build (2026-11-27). The stream guard (`core/oneStream.ts`) lets the newest pick win, so pressing channel up five times quickly opens one channel, not five in turn, which is faster on a stick and still never two at once.
- **What Vega supplies itself**, because Hermes has no WebCrypto ECDH or `DecompressionStream`: `platform/crypto.ts` gives `@tuned/shared` the WebCrypto calls it needs (P-256, HMAC-SHA256, AES-GCM, SHA-256) from `@noble/curves`, `@noble/hashes` and `@noble/ciphers` (pure JavaScript), and gunzip from `pako`; a test opens a box sealed by the phone page's own `seal.js` through them.

## What's in the first version

- **Sign in from your phone** (`SignInScreen`): the stick shows the code and QR of the existing relay ([onboarding](onboarding.md)), and the phone at tunedplayer.com/tv either sends a playlist (opened by `@tuned/shared`, the same box format as `core/TvHandoff`) or signs the stick in to a Tuned account. Typing an Xtream login with the remote's keyboard is there too, for someone without a phone.
- **Premium comes with the Tuned account**, as on the Fire OS build (Melvin, 2026-11-27: "Tuned account only"): no Amazon In-App Purchasing, no prices, no buy buttons and no link to a store or the website. A signed-in account with Premium takes a seat (`/api/account/seat`, build `vega`), and "full" alone locks; offline, the stick keeps what it last heard. Check again shows a spinner and says how it ended.
- **Live TV**: categories down the left and channels beside them, both windowed lists, opened from the cache at once and refreshed after the first screen is up; the first download shows numbered steps with bytes of the full size (or bytes so far), and how much longer when it can tell.
- **The player**: only video until a key; OK shows the channel's name and now and next, which hide themselves; up and down change channel while the controls are hidden; Back closes it. A stream that won't play says so in words with Try again.
- **Movies and Shows** (Melvin, 2026-11-27: "add movies and shows to the vega stick app"): Live TV, Movies, Shows and Settings sit in a row of tabs along the top (`TopBar`). Each of Movies and Shows has its categories down the left and a windowed grid of posters beside them, in the order the tab's Sort button says (below). An Xtream server's movies and shows download after Live TV is on screen (after the first download, and with every refresh), in 4 numbered steps with bytes and time left, shown in the corner while saved ones are on screen or full screen when there are none yet, with Try again on a failure; they're kept on the stick in chunks under `tuned:library` and read after the first screen, so Live TV still opens at once. An M3U link's movies and episodes come from the same file as its channels, an episode going to its show by the name before "S01E02". A movie's page has Play, or Resume from where it was left and From the start; a show's page has its seasons and episodes, each episode with its own name where the provider gives one rather than "S1 E1" (Melvin, 2026-11-17), and an Xtream show reads its episodes as it opens (`get_series_info`, one small request, a spinner, then the list or Try again). Movies and episodes play their own file (mp4, mkv) through the same one-connection guard; OK pauses, left and right skip 10 seconds, and where each was left is kept (the last 300, under `tuned:positions`), finished ones starting over.
- **Search, favourites and TMDB details** (Melvin, 2026-11-27: "add search, favourites and TMDB details to the Vega app"). These use `@tuned/shared/search`, `/favourites` and `/tmdb`, which the Samsung app takes too.
  - **Search** is a tab beside Live TV, Movies and Shows. It matches channels, movies and shows as Android's `core/Search` does: accents and punctuation don't count, and every typed word must start a word of the name. Channels come first. A channel plays; a movie or show opens its page, and Back returns to the search.
  - **Favourites**: hold OK on a channel to star it, or use Add to Favourites on a movie's or show's page. A star shows on the row or poster, a line on the right of the tabs says what changed, and Favourites becomes a category after All in Live TV, Movies and Shows. They're kept under the Samsung app's key (`favourites.current`) and cleared on sign-out.
  - **TMDB** fills a page once it's read: the summary when the playlist has none, genres, running time, rating, the backdrop, the cast, and each episode's real name from TMDB (Melvin, 2026-11-17). Answers are kept on the stick for 30 days, and a miss is retried after a day. While TMDB is asked, a spinner shows; when it can't be reached, a line says the playlist's own details are showing.
  - The key is `TMDB_API_KEY`, the Android release's secret, written into `src/platform/keys.ts` by `scripts/keys.mjs` before a release build. It isn't routed through Tuned's server (Melvin declined a key proxy, 2026-11-17). Without the key, the feature stays off. Settings shows TMDB's required notice.
  - Trailers are left out, since the stick can't open a YouTube player.
- **Sorting, hiding adult and 24/7, and Continue watching** (Melvin, 2026-11-27: "make the vega and the tizen apps feature complete with the android app"). These use `@tuned/shared/sort`, `/filters` and `/progress`, which the Samsung app takes too.
  - **Sort** is a button beside the grid's heading in Movies and in Shows. OK steps through Android's five orders: Playlist order (the default), Recently added (the provider's `added`, or `last_modified` for a show), Newest, Top rated (TMDB's rating once a page has read it, else the provider's, as the poster shows it) and A to Z ("The Office" under O). Each tab keeps its own, on the stick, across restarts. Anything without the value sorted on goes last, in playlist order.
  - **Settings › Content** has Hide adult categories (on by default, as on Android, where they stay hidden until unlocked) and Hide 24/7 channels (off by default). Both use Android's own rules (`core/Classifier.isAdult` and `core/RoundTheClock`, ported to `filters.ts`), on a category's name and the item's own, and apply to Live TV, Movies, Shows, search and channel flipping. Android's parental PIN to show adult categories comes with profiles and PINs; until then the switch itself turns them back on.
  - **Continue watching** is the first category in Movies and in Shows whenever something there is half watched: the newest unfinished movie, or a show's newest unfinished episode, newest first. One watched past 95% leaves it and starts over next time. Positions are now kept with their movie or show (the last 300, under `progress.current`); ones kept before (`tuned:positions`) carry over, movies straight into Continue watching.
- **More than one playlist** (Premium, as on Android; [premium](premium.md)). Settings › Playlists lists every playlist on the stick by its name, or its server's host (never the username or password), with In use beside the open one and Use and Remove beside the others. Add another playlist opens the phone sign-in, or the form, with Back to Settings; without Premium it says that more than one playlist is Premium. A phone or an account backup that sends several adds them all with Premium, and only the first without; a login already on the stick opens it rather than adding it twice.
  - Only the open playlist's channels and movies are kept on the stick (they're big and the stick's storage is small), so Use downloads them again, with the same numbered steps as the first sign-in. If that fails, Back or the Playlists button returns to Settings to pick another.
  - Favourites and Continue watching are each playlist's own (`favourites.<id>`, `progress.<id>`, the Samsung app's keys). The first playlist's id is `current`, so what it kept before there could be several stays. The list is under `tuned:playlists` and the open one under `tuned:playlist`; `tuned:login` is always the open one's login.
  - A download still running for the playlist left behind is dropped when it ends, so it never lands on the next one.
- **The guide grid, catch-up and reminders** (Android's grid guide, [playlist](playlist.md)). They use `@tuned/shared/guide` (the Samsung thread's) and `@tuned/shared/reminders` (this thread's, which the Samsung app takes too).
  - **Guide** beside Live TV's heading switches the channels between the list (the default, as on Android) and the grid, and the choice is kept. The grid shows the open category's channels down the side and two hours across, with a line at the current time, the day in the corner, and the focused programme's channel, times, title, description and what OK does above it.
  - Each programme is its own focusable box, so the stick's own focus moves between them; one beyond each edge of the two hours is laid out out of sight, so left and right step on to it and the window follows. The rows are a windowed list.
  - **Where the guide comes from**: an Xtream server's is read a channel at a time (`get_simple_data_table`, which includes past programmes) for the rows on screen and a few either side, two at once, so the stick never holds a whole guide; a row that can't be read shows "…" and is asked for again when it comes back on screen. A link's guide is the login's, or the one its `#EXTM3U` line names (`url-tvg`), downloaded once a session when the grid opens, with its progress over the grid and Try again on a failure. React Native can't stream a download, so the whole file arrives before it's read in pieces, keeping only this playlist's channels from 2 hours back (or as far as recordings go) to 2 days ahead. The list's now and next stays as it was (`get_short_epg` when a channel plays).
  - **OK**: on what's on now, the channel plays; on a past programme of a channel that keeps recordings (↺), the recording plays from its start through the same one connection (`catchUpLink`: Xtream's timeshift in the server's time zone from `server_info.timezone`, or a link's `catchup`, `catchup-source` and `catchup-days`, ported from core/CatchUp.kt), and it seeks like a movie but keeps no position; on one still to come, a reminder is set or cleared (⏰), with a line at the top saying which.
  - **Reminders** are kept per playlist (`reminders.<id>`). Vega can't wake an app that isn't running, so they come while Tuned is open, and the grid says so: when the programme starts (or the app opens in its first 10 minutes), a banner over any screen but the player says what is starting where, with Watch and Not now. It never takes the remote's focus. Ones that ended while the app was closed are dropped.
- **Live events and auto-tune** ([events](events.md), [auto-tune](auto-tune.md)). They use `@tuned/shared/events` (this thread's, which the Samsung app takes too): Android's `core/Events`, `ChannelEvents`, `EventChannels` and `Tuner` rules, ported with their tests' cases, with no regex lookbehind and no `\p{L}`, which Hermes lacks, and with zone rules for the time zones names give (ET, PT, GMT, CET, AEST and the rest) when the engine's `Intl` can't do time zones.
  - **Live events** is the first row above Live TV's categories whenever the playlist has sports or pay-per-view channels. It lists the next 36 hours' games, fights and pay-per-views under On now, Later today and Tomorrow, one row per event with how many channels show it, and the time ("Live", "9:00 p.m.", "Sat 9:00 p.m.", or "No time" for a name that gives none).
  - **Where events come from**: the guide of each sports or pay-per-view channel, and the channel's own name when its guide lists no event ("PPV 7: UFC 312 10PM ET", read as on Android; a time with no zone is in the stick's own). An Xtream server's guide is read a channel at a time, two at once, for at most 300 sports channels, with how many are read so far and time left, and kept for the grid as well; a link's is its guide file, as for the grid. The list is built again each minute, and once every ten channels while they're read.
  - **OK** on an event that's on, starts within the hour or gives no time auto-tunes it. On a later one it sets or clears a reminder (🔔) that, when the event starts, offers Watch, and Watch auto-tunes it.
  - **Auto-tune** gathers the event's channels and every other channel whose name, or whose guide now or within the hour, has the event's words ("UFC 335" also finds "UFC335"), ranks them as Android does (failed in the last 6 hours last, then US and Canada, other English, no country tag, other languages; then known to work in the last week, listed in the guide, and sharper by name), and tries them one at a time through the one connection: an error, or no picture within Settings › Auto-tune's wait (5, 8, 12 or 20 seconds, 8 by default), moves on to the next. The player says "Finding a working channel: 2 of 9", the one that plays shows Next stream for when it's the wrong event, up and down move through the same list, and when none plays it says so with Try again. What worked and what failed is kept per playlist (`health.<id>`, the last 500 channels). Back returns to Live events. A stick has no picture height to measure, so quality comes from the channel's name, and there is no lowest-picture setting.
  - **Following** teams, leagues and fighters is typed on the phone or the website, as on Android TV ([TV](tv.md)); Live events says so. Reading what's followed from the account's backup, to list those events first, comes with the next pull request, which reads the backup for profiles too.
- **One stream connection, ever**: `core/oneStream.ts` closes and de-initializes the old `VideoPlayer` before the next one opens, so two streams never overlap; nothing prefetches and there is no preview tile.

- **Words**: every string is in `src/ui/strings/en.ts`, including the download steps, the failures and the account lines that used to sit in `core/` and `app/model.ts`. They say "movies", never "films" (Melvin, 2026-11-27: "instead of films can you call them movies", as on Android and the Samsung app). Each of the Android app's other 11 languages has its own file beside it (Melvin, 2026-11-27: "translate both apps into the 10 languages"), and `main.tsx` picks one from the stick's language (`platform/language.ts`: React Native's `I18nManager` locale, then `Intl`) before the first screen draws, with no picker ([languages](languages.md#the-tv-apps-melvin-2026-11-27)). `test/strings.test.ts` fails when a language lacks a line, and `npm run screenshots` also draws Live TV, Movies, a show and Settings in German, Arabic and Chinese. Mirroring Arabic on a real stick is left to Vega OS and hasn't been checked on one.

## Left out, and why

- **Downloads, recording, live rewind, casting, picture-in-picture, the widget and the self-updater**: a Vega app has no background service for long downloads, no local server for Tuned's segmenter, and the Appstore updates the app.
- **HLS-only playlists** (`.m3u8` channels) play through URL mode where the stick's player manages them; Amazon only promises adaptive streams through a JavaScript MSE player, so Amazon's patched hls.js (a tarball from Amazon, not npm) comes in a later pull request if a provider needs it.
- **No sleep timer, no second video** ([scope](scope.md)).

## Building, testing and shipping

- **CI** (`ci.yml`'s "Vega (Fire TV)" job, run when `tv/vega/` or `tv/shared/` changes, from `scripts/ci-changes.mjs`'s `vega` output): type check, the Jest tests on Node (including opening a box sealed by the phone page's own `seal.js`), and every screen drawn in the browser preview, kept as the `vega-screenshots` artifact. The `.vpkg` build needs Amazon's Vega SDK (`get_vvm.sh`, Ubuntu x86_64 or macOS), which the same job installs with `NONINTERACTIVE=true SKIP_VVD_INSTALL=true`, then uploads the `.vpkg` files as the `tuned-vega-vpkg` artifact.
- **The browser preview** (`npm run preview` in `tv/vega/`) draws the same screens with React Native for Web and stand-ins for Amazon's modules, with a `<video>` player, for screenshots at 1920 × 1080 ([screenshots](screenshots.md)). It's how the screens are checked without a stick; playback and speed are only checked on a real stick.
- **On a stick**: Melvin's Fire TV in developer mode, installed with `vega run-app` (or Vega Studio) from the `.vpkg`; real streams only work on his network.
- **The Amazon Appstore**: the `.vpkg` goes up by hand in the Developer Console, alongside the Fire OS APK where the Console allows one listing for both _(check)_. Every production release still needs Melvin's go-ahead, and he submits it.
