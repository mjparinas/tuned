# Trakt

From the app audit, Melvin picked Trakt (item 14): what's watched in Tuned shows up in the person's Trakt history and "up next", alongside every other app they use.

**Signing in** (`data/TraktAccount`). Trakt's device code: Settings › Playlists and account › Connect Trakt shows a short code and trakt.tv/activate, which works the same from a phone, a computer or a TV remote, and Tuned never sees the Trakt password. A button beside the code copies it, for pasting on trakt.tv/activate when that's open on the same phone (Melvin, 2026-11-18); the Google Drive sign-in code has the same button (`ui/settings/SignInCode`). The dialog asks Trakt every few seconds (slower when Trakt says so) until the code is entered, refused or runs out. The tokens are sealed with a key in the Android Keystore (`data/KeystoreBox`), like the login. The backup in the Tuned account carries them, so connecting Trakt once covers every device; the newer session wins and the copy never signs a device out ([accounts](accounts.md), Melvin, 2026-11-19). They are renewed a day before they expire; if Trakt no longer accepts them (revoked on trakt.tv), Tuned signs out of Trakt too. Disconnecting tells Trakt to drop the token.

**Scrobbling** (`player/TraktScrobbler`, `core/Trakt`, with tests). Films and episodes only: start when one plays, pause when the person pauses (buffering isn't a pause), stop when it ends, the next one starts or the player closes, each with how far through it is (for Next, how far the last one got, not where the next one starts). Trakt marks it watched from 80%. Trakt matches by title and year (films) or show title and year with the season and episode number, so no TMDB key is needed; names are cleaned of the provider's tags the same way as for ratings. Live TV, catch-up and recordings aren't sent. While casting, the spot comes from the TV, not the phone's stopped player. A pause or stop under 1% isn't sent, since there is nothing to save and Trakt turns it down ("progress_too_low", HTTP 422, 2026-11-18). A failed send is logged with Trakt's answer and dropped; the next play or pause sends the state again. Settings › Playlists and account › Scrobble what you watch turns it off without disconnecting (on by default).

**Importing watched history** (`data/WatchedHistoryImport`, shared with [Simkl](simkl.md), Melvin, 2026-11-22: "do trakt history import"). Settings › Playlists and account › Import watched history, once signed in, pulls Trakt's watched films (`/sync/watched/movies`) and shows with season progress (`/sync/watched/shows?extended=progress`), page by page (250 and 100), matches them to the playlist the same way scrobbling does (cleaned title and year when both sides have one; every matching copy in every group), and marks those items watched for the profile in use at Trakt's `last_watched_at`. Already-finished items with a newer time in Tuned are left alone. The row shows a spinner and named steps from the tap (reading the playlist, fetching films, fetching shows, marking with a count and ETA), then how many films and episodes were marked, or that nothing matched, or Try again on a failure. Live TV isn't imported. Nothing is sent back to Trakt.

**The app's keys.** Trakt identifies the app by its client id alone: it stopped issuing client secrets (new apps sign in with PKCE or a device code, and `client_secret` is optional and deprecated on every `/oauth` call), so Tuned sends none (Melvin's Trakt app, 2026-11-18, shows "Client Secret: Not issued"). The id comes from the release workflow's secret `TRAKT_CLIENT_ID` into `BuildConfig` and is never committed. A build without it (debug builds, pull requests) hides everything Trakt.

**On the Samsung and Vega TV apps** (Melvin, 2026-11-27: "make the vega and the tizen apps feature complete with the android app"). `@tuned/shared/trakt` (`tv/shared/src/trakt.ts`, with tests) does what `core/Trakt` and `data/TraktAccount` do here, shaped like `@tuned/shared/simkl` so both TV apps use the two alike: the device code at trakt.tv/activate with the client id alone, the same poll answers (400 wait, 429 a second slower, 404 and 410 ran out, 409 and 418 refused), renewal a day before the token ends and signing out when Trakt refuses it, scrobbling with names cleaned as for TMDB (and TMDB's id when the app has one), nothing sent under 1%, and the watched history page by page (250 films, 100 shows) for an import. It takes the sign-in and the Scrobble switch from the account's backup (`copy.trakt`, `copy.traktScrobble`), so connecting Trakt on the phone covers the TV. The TV keeps the tokens in its own sealed store and never logs them. The screens that use it come in each app's own pull request.
