# Playlist and guide

**Source.** Xtream Codes-style servers: `get.php?type=m3u_plus&output=ts` for the playlist and `xmltv.php` for the guide, both built from the server, username and password (`XtreamUrls`). The default server is `http://eros4k.ddns.net`, editable at sign-in and in Settings (Melvin, 2026-11-17). Other providers can be added as a plain M3U link or an M3U file, with an optional XMLTV link; a plain playlist without one uses the guide its `#EXTM3U` line names ([onboarding](onboarding.md)).

**When the M3U download is blocked** (Melvin, 2026-11-17: "fix", after the provider compatibility review). Some providers turn `get.php` off, or answer it with an error page, while their JSON API (`player_api.php`) still works; others leave series out of the M3U. On an Xtream login Tuned then reads the API instead (`core/XtreamApi`, `data/XtreamImport`): live channels and films from `get_live_streams` and `get_vod_streams` with their categories, and shows from `get_series`. The links it builds are the ones `m3u_plus` would list and end in the same stream ids, so favourites, history and downloads carry over either way. The API lists shows without episodes, so each show is first stored as one stand-in row (link `xtream-series:<id>`), and opening it fetches its episodes (`get_series_info`) and swaps them in; a refresh keeps fetched episodes in place of the stand-in. When the M3U downloads fine but has no shows, only the shows come from the API. When the API fails too, the M3U's error is the one shown. A line in a playlist that isn't a link (`://`) is no longer read as a stream, so an HTML error page reads as an empty playlist and never replaces a good cache.

**Sections.** Xtream URLs carry the section in the path (`/live/`, `/movie/`, `/series/`), which decides Live TV, Movies or Shows. `m3u_plus` writes live links with no section (`/user/pass/123.ts`), and those are always live, so a live category such as "UK| Sky Cinema" or "US| Kids Shows" stays in Live TV (2026-11-17, provider compatibility review). Without either, a film file (`.mkv`, `.mp4`, `.avi` and the like) is a film, or an episode when the category says shows or series; a category of channels ("Movie Channels", "24/7 Cartoons") is live; then the category name decides, in English, French, Spanish, Portuguese and German (`VOD`, `Movies`, `Películas`, `Filme`, `Series`, `Séries`, `Serien`…); anything else is live.

**Shows.** Episodes are grouped by the show name read from the title (`Show S01 E02`, `Show S01E02`, `Show S01 EP02`, `Show 1x02`, `Show T01E02`, `Show Season 1 Episode 2`, and the same in French, Spanish, Italian, Dutch and German); a title without numbering is one episode of its own show, so nothing disappears.

**Countries** (Melvin, 2026-11-17: "toggle controls in the settings that allow you to hide certain countries' content"). Providers seldom fill `tvg-country`, so the region usually comes from the category prefix. Since the provider compatibility review (2026-11-17), it is read in this order, so other providers' styles work too:

1. A tag or language name and a bar at the start of the stream's own name (`HINDI| Sony Max`, `IN | Colors`), ahead of the category, because providers file other countries' channels under their own (`US| MOVIES NETWORK`; Melvin, 2026-11-18, seeing Hindi channels in Movies with only US and Canada on). A colon (`IT: Chapter Two`) or a word that isn't a tag (`NFL | Week 1`) doesn't count.
2. A flag emoji in the category (`🇬🇧 Sports`).
3. A tag at the start of the category, with any symbol after it: `US| News`, `|CA| Kids`, `[FR] Cinéma`, `UK: Sport`, `US » News`, `US ➤ News`, `4K | US Movies` (quality tags are skipped). Country and language names written out count too (`UNITED STATES | News`, `Canada: News`, `ENGLISH | Movies`, `LATINO | Deportes`, `EXYU | HRT`).
4. A category that is only a country (`UK`, `USA`, `Germany`).
5. A country or language written out at the start of the category with no symbol after it (`SWEDEN HANDBOLLSLIGAN PPV`, `INDIA MOVIES`, `UNITED STATES NEWS`), added 2026-11-18 when Melvin, with only US and Canada on, still saw Swedish channels. Only whole names of four letters or more count, and names that start other things (Georgia, Jordan, Jersey, America and a few more) never do. A continent in front (`ASIA | INDIA MOVIES`, `EUROPE | DE Sports`) is looked past for the country after it; on its own it is the region (`ASIA`, `EUR`, `AFR`, `NORDIC`). Countries written in their own language count the same way (`SVERIGE`, `SVENSKA`, `NORGE`, `DANMARK`, `SUOMI`, `DEUTSCHLAND`, `ITALIA` and so on), as do `NORDIC` and `SCANDINAVIA`.
6. `tvg-country`, when it names a known country, as a code (`US`, `gb`) or a name (`United States`). `INT` or `World` name nothing and fall through. In `tvg-country`, `AR` is Argentina (ISO), so it reads as Latino, not Arabic. Since 2026-11-18 it comes after the category (Melvin: hidden countries must stay hidden), so `|EXYU| Filmovi` with `tvg-country="HR"` reads as Ex-Yugoslavia; it still decides for categories with no country (`News`).
7. The same in the channel name, then a tag in brackets at the end of the name (`ESPN (US)`).
8. `tvg-language` (`English`, `eng`, `en`), read as the tag that speaks it, so the language switches work for playlists (such as iptv-org's) that only give a language.

Only real tags count: the ISO country codes plus the language and area tags providers use (`EN`, `AR`, `LAT`, `EX`, `KU`, `AFR`). So `PPV | UFC`, `NBA | League Pass`, `SKY | Sports`, `BT | Sport` or `CNN [US]` no longer add "UFC", "NBA", "SKY", "BT" or "CNN" switches to Settings. Settings › Countries lists every region found A to Z by name (the JDK's English name for codes Tuned has no short name for) (Melvin, 2026-11-18: "countries should be sorted alphabetically not by number of streams"), with how many streams each has; turning one off hides it in every list and search. Streams with no region always show. Codes with no symbol after them (`US NEWS`, `ESPN US`) are not read, because "US Open" or "Join Us" would match too. Country filtering applies the same way to Live TV, Movies and Shows, and to sports, PPV and event channels: nothing overrides a country that is turned off.

**New countries follow the rest** (Melvin, 2026-11-18: "this is configured for only US/Canada"). Settings keeps the countries turned off, so a country first found by a later refresh, or by a better rule, used to show. Now the app remembers which countries it has seen (`seen_regions`, kept on the device only), and a new one starts hidden when most of the known ones are hidden, and shown otherwise (`core/NewRegions`). Someone who kept only US and Canada keeps seeing only those; someone who hid one or two still sees new ones. It runs at app start (to remember what's there) and after each playlist refresh.

**Titles in the grids** (2026-11-18, Melvin's screenshot of "Ex - Dogtanian" and "ES Mixed by Erry"). Movie and show posters and Continue watching show the name through `core/Titles`, like search and details already did, so a language tag in front comes off. `Ex - ` / `EXYU - ` in any case and a known country tag followed by two or more spaces come off too.

**Languages** (Melvin, 2026-11-17: "is there already channel filtering by country / language?"). Providers tag streams by country or language, not by spoken language, so a language is the set of tags that speak it (`core/RegionLanguages`): English is EN, US, UK, CA, AU, IE and NZ; Spanish is ES, MX and LAT; and so on. Settings › Countries and languages lists those languages above the countries, with a search box on top that filters both as you type, by name or tag, ignoring case and accents (Melvin, 2026-11-18: "countries and languages should have a real time search"), and each switch turns all its tags off or on together, so nothing new is stored. Countries with several common languages (Belgium, Switzerland, India) belong to none and stay under their own switch, so a language never hides more than it says. A language's switch shows on only while all its countries are on; with some on, it shows off and its line says which ("Only CA, US on"), so keeping only US and Canada never looks like all of English (Melvin, 2026-11-18). Turning it on shows all its countries; turning a country on never turns on the others.

**Hidden groups** (Melvin, 2026-11-17: "hiding channel groups"). On the home screen, picking a group's chip shows an eye on it that hides the group; Settings › Hidden groups lists every group in Live TV, Movies and Shows with a switch to bring any back. Hiding one says so in a bar with **Undo**, which brings it back and picks it again (2026-11-18, from Melvin's UI review: a toast that couldn't be taken back made a slip costly). A hidden group stays out of lists, search, auto-tune and channel flipping. Keys name the section (`g:<kind>:<group>`), so a Movies "Action" and a Shows "Action" are separate. They travel in the same query parameter as hidden countries, so no query needed a second list.

**24/7 channels** (Melvin, 2026-11-17: "Add the ability to hide 24/7 streams"). Settings › Content › Hide 24/7 channels leaves out live channels whose category or name says 24/7, 24-7, 24 7, 247 or 24x7 ("24/7 Friends", "US| 24/7 CARTOONS", "247: The Simpsons") from Live TV, search, auto-tune and channel flipping. It applies to Movies and Shows too (Melvin, 2026-11-18: "the hide 24/7 functionality should apply to movies and shows"): films, shows and their categories labelled 24/7 leave the grids, the category chips, Continue Watching and search. Off by default, since many people watch them. Like the empty event slots, it goes by the name (`core/RoundTheClock`, applied in SQL as a hidden key), so nothing is stored per stream.

**Stream headers** (2026-11-17, provider compatibility review). Some providers only serve a stream to a given player or page. A playlist says so with `#EXTVLCOPT:http-user-agent=…` or `http-referrer=…` lines before the link, or Kodi's form after a `|` (`link|User-Agent=…&Referer=…`). Both are kept in the stored link in Kodi's form (`core/StreamLink`), so no column was needed. The player sends them on every request to that stream's host (including an HLS stream's segments) in place of the app's user agent; the channel scan sends them too, so a stream isn't called dead for want of them; downloads send the user agent. Casting sends the bare link, since a TV takes no extra headers. Stable ids, sections and catch-up ignore the headers.

**Adult categories** are hidden by default (Settings › Content › Show adult categories). A stream is adult when its category or name says `XXX`, `Adult(s)`, `18+` or `+18`, `Porn`, `Erotic`, the word in other languages (`Adultos`, `Adulte`, `Adulti`, `Erwachsene`, `Volwassenen`), or names a studio channel (Playboy, Hustler, Brazzers, Penthouse, Dorcel, Red Light, Babestation). "Adult Swim" and "Young Adult" are not adult, unless the category says so anyway. On Xtream logins, a live channel the server itself flags `is_adult` is adult too, whatever its category says: the catch-up step already streams `get_live_streams` after each playlist import, and marks those channels as it goes (2026-11-17).

**Downloading (2026-11-17, after v0.1.0 failed to sign in with "Software caused connection abort").** Melvin's provider serves playlists of about 400 MB from slow servers. So each file is first saved to disk by `Downloader` and only then read into the database:

- Timeouts are long (30 s to connect, 3 minutes between bytes), since slow panels can take minutes to start answering.
- A dropped connection is retried with backoff (2 s up to 30 s). Only attempts that make no progress count, and it gives up after six in a row.
- It resumes with HTTP Range only when the server names a validator (ETag or Last-Modified, sent back as If-Range), so a changed file is never stitched onto an old one. Otherwise it starts over.
- The body is saved as sent (gzip stays gzip) and unzipped while reading.
- The refresh runs in a WorkManager worker that is promoted to a foreground service, so it keeps going when the screen turns off or another app comes forward. The connection abort came from Android cutting a long download that ran in the sign-in screen.
- Sign-in now only checks the login with `player_api.php` (a small answer) and then opens the app. The first screen shows a progress bar (MB of MB, then items saved), as does the notification. A thin bar above the lists shows later refreshes that the person started (Refresh now, pull to refresh, a new playlist). Scheduled background refreshes run unseen (Melvin, 2026-11-18: "i see 'saving channels' a lot, why"): the cache stays usable throughout, so there is nothing to wait for.

**Caching.** Each refresh reads the downloaded file into Room in batches of 1,000, each its own short transaction. It used to be one transaction for the whole file, but Room's paged lists read inside a transaction too, so browsing and search sat blank until a big guide finished saving (Melvin, 2026-11-17: "Downloading the guide seems to block any searching"). Writing the playlist in place wasn't enough either (Melvin, 2026-11-17: "Search is not working while downloading"): each batch made every open list and search start over, so on a big playlist they never finished. Now the playlist goes into a side table (`items_next`) and, once it's all in, only the streams that differ (removed, renamed, moved or new) are changed in the live table, 2,000 per transaction, so a search waits at most a moment and each stream is always either its old or its new self. The first download has no cache to keep, so it fills the lists as it arrives. The guide is written to a side table (`programmes_next`) and swapped in with one quick copy at the end (`data/db/CacheWriters.kt`). A failed or empty download keeps the old guide and playlist, so the cache is never emptied. Favourites and watch history are keyed by a stable id (the stream id from the URL, the section and the name), so they survive refreshes and a change of login. Favourites keep their own order (Settings › Order favourites, oldest first until changed), and the Favourites filter on Live TV shows them in that order.

**Guide.** Only programmes for channels in the playlist, from an hour ago to _Guide days to keep_ ahead (3 by default), are stored. Gzipped guides are unwrapped by their magic bytes.

**Guide time offset** (2026-11-18, the provider compatibility review; Melvin's standing go-ahead to build the open gaps). A playlist's `tvg-shift` (hours, such as `+3`, `-1.5` or `5:30`, on a channel or on the `#EXTM3U` header for all channels) moves that channel's guide times, for feeds such as a west-coast copy that shares the east-coast guide. The shift is kept in the channel's guide id (`News.us@shift-180`), and the guide import writes a moved copy of that id's programmes under it, so every screen that finds a channel's programmes by id shows the right times with no change. A channel's own `tvg-shift="0"` overrides the header. Channels without a shift cost nothing extra (`core/GuideShift.kt`, with tests). It adds to the guide fixes below: the whole-guide offset and a channel's own offset move a shifted channel further, and a channel's fix reads the unshifted guide entry.

**Background refresh.** WorkManager, periodic, with a network and not on low battery (optionally Wi-Fi only): channels and movies every 12 hours, the guide every 6, both editable (or off). Settings › Refresh now runs it at once. Pull to refresh does the same but is off by default (Melvin, 2026-11-17: "disable swipe down to refresh or maybe add it as a setting"), so a scroll to the top never starts a download; Settings › Pull down to refresh turns it on. A refresh that downloads the same playlist file as last time skips saving it (Melvin, 2026-11-18: "i see 'saving channels' a lot, why"): `data/PlaylistMemo` keeps a SHA-256 of the file the cache came from (salted with the app's version code, so a new parser reads it once more), and an identical file leaves the cache as it is. A cache that came from the Xtream API, or whose shows came from it, is always saved afresh, since those can change while the file doesn't.

**Guide reminders** (2026-11-17). A bell on each upcoming programme in a channel's guide sets a reminder, a few minutes before it starts (Settings › Background, default 5 minutes). Each reminder is a WorkManager job tagged with the channel and start time, so it survives restarts and needs no table; tapping the notification plays the channel. Android 13 and later ask for the notification permission the first time a bell is tapped, and a "no" leaves the reminder unset. A reminder more than 30 minutes late says nothing, and signing out cancels them all.

**New episodes** (Melvin, 2026-11-17). Opening a show records the episodes it has (`seen_episodes`, by stable item id, Room v8). After a refresh adds more, the show's poster reads "12 episodes · 2 new", and the next time the show opens those episodes say New. They count as seen from then on. A show never opened has nothing new, so a fresh playlist doesn't light up everywhere.

**Grid guide** (2026-11-17, Melvin asked for a full TV guide like TiviMate). A button beside search on Live TV, and Settings › Show Live TV as a guide grid, switch the channel list to a grid: channels down the side, time across the top, a line at the current time, and the day in the corner, which turns into "Now" to jump back once the view scrolls away. The list stays the default. The grid uses the same paged channel list as Live TV, so groups, favourites, recent and search narrow it too. Each row reads its channel's programmes in six-hour blocks through the (channelId, start) index, only for rows on screen, and keeps them in a small cache that a finished refresh empties, so a playlist of thousands of channels costs only what is on screen. A swipe moves the cells without recomposing them; rows only recompose when the view crosses a half hour. It scrolls back an hour, or as far as the longest catch-up a channel keeps, and forward as many days as the guide keeps. Tapping what's on now plays it; any other programme opens that channel's guide, where the reminder bell and catch-up replay are, so the grid adds no second set of buttons. On a TV, moving the remote onto a programme off either edge scrolls the grid to it. The layout rules (ticks, blocks, how far it scrolls) are in `core` (`GuideGrid`) with tests.

**Catch-up** (2026-11-17, Xtream `tv_archive`). Each playlist refresh also asks the server which live channels keep recordings (`get_live_streams`, read one channel at a time) and for its time zone (`player_api.php`), and saves the channels with recordings in their own table. The guide then keeps those channels' past programmes for as many days as the server keeps (at most 7); other channels still keep only the last hour. In a channel's guide, a past programme within that window has a replay button, and tapping it plays the recording from the start through the server's `timeshift` link, which is read in the server's time zone. A recording plays on its own (no next or previous), can be paused and skipped through, and isn't saved to Continue Watching. Plain M3U playlists get catch-up from their own attributes (2026-11-18, from the gap review Melvin asked for: "what else are we missing"): `catchup` (or `catchup-type`), `catchup-days` (or `timeshift`, `tvg-rec`) and `catchup-source`, on each channel or once in the `#EXTM3U` header for all of them, the way Kodi's IPTV Simple and TiviMate read them. The modes are `default` (the template is the whole link), `append` (added to the live link), `shift` (`?utc=…&lutc=…`, also when a channel says only `timeshift="3"`), `flussonic` (`index-<start>-<duration>.m3u8`, or `timeshift_abs-<start>.ts` for `/mpegts`) and `xc` (Xtream's timeshift link built from the live link). Templates take `{utc}`, `{start}`, `{utcend}`, `{end}`, `{lutc}`, `{now}`, `{timestamp}`, `{duration}`, `{duration:N}`, `{offset}`, `{Y}` to `{S}`, `{utc:Y-m-d}` style formats and `${(b)yyyyMMddHHmmss}` / `${(e)…}`, each with or without a `$`. A channel that names catch-up but not its days gets 5, as in Kodi, and never more than 7. The rows go in the same catch-up table, keyed by the link (or its Xtream stream id) with the mode and template beside the days (Room v16), so the guide's replay button and the grid work the same as for Xtream. The rules are in `core` (`M3uCatchUp`, `CatchUpTemplate`) with tests.

**Watch later and watched** (Melvin, 2026-11-17: "add to watch later, marked as watched"). Films and shows can be saved to Watch later from the film page, the show page, or a poster's long-press menu. They appear in a row across the top of Movies or Shows, under Continue Watching. The list keeps each title and poster in its own table (`watch_later`, Room v7), so it shows without looking anything up, and it syncs between devices. A film or episode counts as watched once played to 92%, or when marked by hand: the check on the film page, the check beside each episode, "Mark season watched", or the poster menu. Marking watched saves a finished entry in the watch history, so it also leaves Continue Watching; marking unwatched forgets the position. Watched films show a check on their poster.

**Search** (Melvin, 2026-11-17: "search takes a long time"). Names are searched through an FTS4 full-text index (`items_fts`, kept in step by triggers), matching every typed word by its start: "top gu" finds "Top Gun", but "gun" no longer finds "Topgun". On a copy the size of a large playlist (480,000 streams and 480,000 programmes) show search went from 524 ms to 21 ms, channel search from 283 ms to about 65 ms, and film search from 25 ms to 5 ms. Guide titles are still matched anywhere, but only among programmes on now or within the hour, through an index on start times.

**No dead ends in a tab's search** (2026-11-18, UI review). When a search on Live TV, Movies or Shows finds nothing, the list says so and offers Search everything with the same words, and the Search everything button beside the box carries over what was typed, so nothing is typed twice.

**Account status** (2026-11-17, from the app audit). Settings › Account shows the subscription (Active, Trial and so on), when it ends (with "in 3 days" in the last week) and how many of its connections are in use, from Xtream's `player_api.php` (`AccountRepository`, rules in `core/XtreamAccount`). It is a small answer, not a stream, asked when Live TV opens and when Settings opens, and kept for three minutes, so nothing waits on it. Plain M3U logins have no such call and show nothing.

When a fresh answer says every connection is in use, and it was taken while Tuned had no stream of its own (no player and no download open, and the last one closed at least a minute before, since servers are slow to stop counting one; a running download used to count as another device, 2026-11-18), the player doesn't open the stream: it says the connections are in use, probably on another device, and waits for play to be pressed. That keeps a 1- or 2-connection account from going over its limit by accident.

**Guide fixes** (2026-11-17, from the app audit: wrong or missing guide data is one of the most common complaints). The rules are in `core/GuideFixes.kt`, with tests.

- **Guide time offset** (Settings › Background) moves the whole guide by half an hour or by whole hours, up to 12 either way. It applies at once to the guide on the device, and every refresh uses it. The change runs under the refresh lock, so it is never applied twice.
- **Extra guide links** (same place) are XMLTV links read after the provider's guide in the same refresh. They only fill channels that the guides before them left empty, and one that fails leaves the rest as it is. They are stored encrypted with the login, because such links often carry a key, and the dialog shows only their host.
- **A channel's own fix** is set from the calendar button on its guide page. It can move that channel's times, take its programmes from another guide entry, or both. The other entry is picked from the guide's channel list (`guide_channels`, saved at each refresh). The channel gets its own guide id, `fix:<id>`, in place of the playlist's tvg-id, and the refresh copies the source's programmes to it with the offset applied. Every screen that reads the guide then shows the fix without knowing about it. A playlist refresh puts the fixed id back (`GuideFixDao.reapply`). A fix shows at once when its source's programmes are already on the device. Otherwise a guide refresh starts. Fixes live in the database (`guide_fixes`), so sync doesn't carry them.
