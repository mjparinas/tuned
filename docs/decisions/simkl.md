# Simkl

Melvin, 2026-11-22: add Simkl support alongside Trakt, so what's watched in Tuned shows up in the person's Simkl history and "watching now", the same way Trakt already does for people who prefer that service.

**Signing in** (`data/SimklAccount`). Simkl's OAuth 2 device code (AUTH V2): Settings › Playlists and account › Connect Simkl shows a short code and simkl.com/pin, which works the same from a phone, a computer or a TV remote, and Tuned never sees the Simkl password. A button beside the code copies it (`ui/settings/SignInCode`), matching Trakt. The dialog asks Simkl every few seconds (slower when Simkl says `slow_down`) until the code is entered or runs out; Simkl never signals a refusal, so walking away and saying no both end as expired. The tokens are sealed with a key in the Android Keystore (`data/KeystoreBox`), like the login. The backup in the Tuned account carries them, so connecting Simkl once covers every device; the newer session wins and the copy never signs a device out ([accounts](accounts.md)). They are renewed a day before they expire; if Simkl no longer accepts them, Tuned signs out of Simkl too. Disconnecting in Settings tells Simkl to drop the token; signing out of Tuned only forgets it on this device, so other devices keeping the same backup stay signed in.

**Scrobbling** (`player/SimklScrobbler`, `core/Simkl`, with tests). Films and episodes only: start when one plays, pause when the person pauses (buffering isn't a pause), stop when it ends, the next one starts or the player closes, each with how far through it is (for Next, how far the last one got, not where the next one starts). Simkl marks it watched from 80%. Simkl matches by title and year (films) or show title and year with the season and episode number; names are cleaned of the provider's tags the same way as for ratings. Live TV, catch-up and recordings aren't sent. While casting, the spot comes from the TV, not the phone's stopped player. A pause or stop under 1% isn't sent. A failed send is logged with Simkl's answer and dropped; the next play or pause sends the state again. Settings › Playlists and account › Scrobble what you watch turns it off without disconnecting (on by default). Trakt and Simkl can both be connected; each scrobbles independently.

**Premium and the app's key.** Simkl is Premium, like Trakt ([premium](premium.md)). The client id comes from the release workflow's secret `SIMKL_CLIENT_ID` into `BuildConfig` and is never committed. Device-code sign-in needs no client secret. A build without the id (debug builds, pull requests) hides everything Simkl. The admin's `simkl` flag can hide it for everyone ([admin](admin.md)).

**Importing watched history** (`data/SimklHistory`, `data/WatchedHistoryImport`, with tests; Melvin, 2026-11-25: "go ahead and build out the 2 small items"). Settings › Playlists and account › Simkl › Import watched history, once connected, works like Trakt's ([Trakt](trakt.md)): one tap reads Simkl's completed films (`/sync/all-items/movies/completed`) and every watched episode of its shows and anime, whatever their status, since a dropped show still has episodes seen (`/sync/all-items/shows` and `/anime` with `extended=full`, `include_all_episodes` and each episode's `watched_at`). Anime uses Simkl's TVDB season and number where it maps one (`full_anime_seasons`), since playlists number anime that way; an anime list that fails is logged and the films and shows still import. They are matched to the playlist the same way scrobbling does (cleaned title and year when both sides have one; every matching copy in every group) and marked watched for the profile in use at Simkl's time; already-finished items with a newer time in Tuned are left alone. The row shows a spinner and named steps from the tap (reading the playlist, fetching films from Simkl, fetching shows from Simkl, marking with a count and ETA), then how many films and episodes were marked, that nothing matched, or Try again on a failure. Trakt and Simkl share the import (`WatchedHistoryImport` with a `Source` each) and the row (`ui/settings/HistoryImportRow`); only the lines naming the service differ. It is a one-off read on a tap, never on a timer, because Simkl suspends apps that poll `/sync/all-items`. Live TV isn't imported, and nothing is sent back to Simkl. The same `SIMKL_CLIENT_ID` covers it; no new key.

**On the TV apps** (Melvin, 2026-11-27: make the Samsung and Vega apps feature complete with Android). `@tuned/shared/simkl` (`tv/shared/src/simkl.ts`, with tests) does what `core/Simkl`, `data/SimklAccount` and `data/SimklHistory` do, for both TV apps: the same device code at simkl.com/pin (`startSignIn`, then `pollSignIn` once per interval, 5 seconds slower after `slow_down`), tokens kept in the TV's store (`simkl.token`, never logged) and renewed a day before they run out, a sign-in taken from the account's backup when it's newer (`simklFromBackup`, `adopt`), so connecting once on the phone covers the TV, `scrobble` with names cleaned as for TMDB and the 1% and 80% rules, and `watchedHistory` reading the same three `/sync/all-items` lists once on a tap. It is shaped like `@tuned/shared/trakt` so the two apps use both alike. The id is `SIMKL_CLIENT_ID` at build time; a build without it hides Simkl. The Vega app has the sign-in and scrobbling in Settings › Simkl, and the Samsung app in Settings › Trakt and Simkl, both without the history import, since a TV app keeps no watched marks ([Vega OS](vega.md), [Samsung TVs](tizen.md)).
